# 独立 LaTeX 工程迁移说明

迁移日期：2026-09-05。原工程：`designpractice`；新工程：`designpracticelatex`。

本次以原工程保存的完整 TeX 为正文基线，结合当前 Rmd 提取原始代码和表格结构，完成一次性整理。交付的是原生 `.tex` 书稿，日常构建只运行 XeLaTeX / latexmk。原工程的书稿、图片和历史出版物均保留。

## 交付内容

- 22 份分章书稿：前言、18 个正文章节、总结、参考文献、相关资料。
- 346 个各级标题、38 幅插图、21 个表格、20 条手工参考文献。
- 原有 109 个代码块全部保留，另将两条漏标记的 Shell 命令整理为代码块，共 111 个代码块。
- 完整复制原 `assets/` 的 55 个文件，包括目前未直接入书的制图源和替代格式；没有使用符号链接。
- 主文件、集中排版配置、字体、latexmk 设置、Windows / Unix 启动脚本和 VS Code 配置。
- 使用说明、来源与改动清单、逐章正文对比结果、结构与哈希检查工具。

## 已修复的问题

### 图引用与图标题

修复了原稿 5 处不规范引用：芯片实现流程、AM 层次结构、建立与保持时间、DFT 扫描链、MBIST。原先漏写 `fig:`、混用括号 / 花括号 / 中文括号、错误组合 `\@\ref` 的地方均改为标准 `\ref{...}`。

全部 38 次图引用都能找到目标。将原来的中文 DFT 图标签改为 `fig:dft-scan-chain`，章节标签也整理成可读的 ASCII 名称；全书 384 个标签没有重复。

修正了 DC 综合过程图错误复用“DC处理对象划分”标题的问题，现为“DC综合过程示意图”。所有图均使用明确的文件扩展名，避免同名 PNG / JPG 被误选。

### 代码与字体

- 从 Rmd 提取原始代码，移除大量 `\NormalTok`、`\KeywordTok` 等逐词高亮包装；原有 109 个代码块的内容与顺序经 SHA-256 核对一致。
- 使用 `CodeBlock` 环境，代码可以直接编辑、自动折行、跨页排版，不调用 Python 高亮器，也不需要 shell escape。
- 将 `make -j$(nproc)` 从错误的数学模式恢复成代码，恢复原 PDF 中因此缺失的中文说明；相应行内命令也正确转义。
- 将漏标记的 `make install` 放入代码环境，区分六个 BusyBox 操作步骤。
- 附带 DejaVu Sans Mono 字体和许可说明，正确显示 `├`、`─`、`│`、`└` 和特殊空格；中文代码字形使用 Fandol，并明确粗体 / 斜体选择。
- 西文正文使用 TeX 自带 Latin Modern，中文使用 Fandol，避免依赖特定电脑的 Windows 字体注册状态。

代码排版采用统一等宽字体和浅色边线，保留缩进；逐词彩色语法高亮不作为运行依赖保留。

### 表格、链接与列表

- 将 10 处表格内 HTML 换行改为 LaTeX 单元格换行，修复地址映射、CRMD 说明、PLL 引脚说明的排版。
- 统一表格字号和列间距，保留跨页及重复表头。
- 将 8 处被当成行内代码的网址改为 `\url`，恢复点击与断行，消除原稿长网址引起的明显横向溢出。
- 修复 8 组原先未被 bookdown 正确识别的列表，覆盖指令分类、中断、Cache、init 进程和芯片布局目标；改成原生 `enumerate` / `itemize`，保留原有条目文字与先后顺序。

### 明显文字错误

修正了“协调工”缺字及句末标点、“需要需要”“架构架构”的重复、“时序知识所有……”中的同音误字，以及“龙芯教育了一个……”缺失谓语等问题。

改动以明确的语法、排版和笔误为范围。没有据此重写芯片技术方案、代码逻辑、寄存器位定义或时序公式。

### 构建与源码维护

移除了 R 软件包参考文献生成、无效 `\nocite{*}` / natbib 模板配置、网页发布脚本等构建依赖。文献仍为原有 20 条手工条目。

采用 `main.tex` + `config/` + `chapters/` 组织；Rmd 不再是新工程的编译输入。新工程不读取原目录。保留原 Letter 开本和大致页边距，前置页使用罗马页码，正文采用阿拉伯页码。字体和代码折行优化后不要求与旧 PDF 页数相同。

## 验收文件

- `content-manifest.json`：章节来源、原始代码及资源哈希、标签映射、明确修订的前后文本。
- `prose-comparison.json`：正文、公式和表格内容的逐章比较结果。
- `verification.json`：对新工程的结构、代码、资源、日志和构建输入检查结果。
- `build-summary.json`：最终目录中的实际构建环境、PDF 页数及哈希。
- `build.stdout`：最终构建的终端输出；完整 LaTeX 日志位于 `build/main.log`。

`scripts/check_project.py` 是可选审计工具，书籍编译不调用它。后续正常写作可以改变原始内容；`--baseline` 报告的差异用于追踪变化。

Windows 启动脚本及编辑器配置已提供，但 Windows 原生执行未在本会话验证；本次已实际验证的是 WSL 路线。HTML / EPUB 发布不在本次独立 PDF 工程范围内。
